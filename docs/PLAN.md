# 計画書：1分筋トレ（kintore-habit）

- 作成日：2026-10-23
- 公開先：GitHub Pages（https://daisuke-awaji.github.io/kintore-habit/）
- リポジトリ：https://github.com/daisuke-awaji/kintore-habit（パブリック）

## 1. 目的

運動が苦手な初心者が、自宅で筋トレを**続けられる**ようにするウェブアプリを作る。
ログインはなし。記録はブラウザの localStorage にだけ保存し、サーバーには何も送らない。

## 2. 背景

UIモックをレビューした結果（`docs/usability-review.md`）、続かなくなる主な原因は次の4つだと分かった。

1. 「毎日やる」という前提が、筋トレの推奨（厚生労働省「健康づくりのための身体活動・運動ガイド2023」では週2〜3日）や体の回復と合っていない
2. 記録が途切れたあとの画面が設計されていない
3. 「今日はこれでOK」の基準が画面ごとにばらばら
4. 初日（まだ記録がない状態）の画面が設計されていない

このアプリは、そのレビューで合意した前提で作る。

## 3. 対象ユーザー

- 運動習慣がない、または一度挫折したことがある大人
- 自宅（集合住宅を含む）で、道具なし・短時間でやりたい人
- 文字が小さいと読みにくい人、色の見え方に個人差がある人も含める

## 4. 設計の前提（レビューで合意したもの）

| # | 前提 | このアプリでの形 |
|---|---|---|
| P1 | 目標は週単位 | 「週◯回」（1〜4回、初期値は2回）。週は月曜に始まる。毎日の連続日数は表示しない |
| P2 | 減らない数字を主役にする | 通算回数・目標を達成した週の数・始めてからの日数 |
| P3 | 「今日のOK」は1つ | どのメニューでも1分やれば「今日のぶん、できた」 |
| P4 | 休むのも計画のうち | 「今日は休む」で回復日にでき、前向きな印で表示する。やらなかった日は印なし（赤や×は使わない） |
| P5 | 途切れても戻れる | ふだんの間隔より長くあいて開いたら（週の目標が1回なら10日、2回なら7日、3〜4回なら5日）「おかえり」画面。休んだ日数には触れず、軽めのメニューを出す |
| P6 | 記録し忘れを直せる | 過去7日分は、あとから記録の追加と削除ができる |
| P7 | 体の調子に合わせる | ふつう／筋肉痛／疲れぎみ／痛みがある、からメニューが変わる |
| P8 | 運動中は見なくても・触らなくてもいい | 大きな数字、音声ガイド、効果音、振動、画面を消さない設定。種目ごとに目標は時間だけにする |
| P9 | 負荷は本人に確認して変える | 終わったあとの「きつかった／物足りない」の答えで、次回のレベルを上げるか下げるかを聞く |
| P10 | 安全 | 始める前の注意、「痛みが出たらすぐ中止」、中止ボタン、医療のアドバイスではないことの明記 |
| P11 | 1日の区切りを選べる | 初期値は朝4時（0〜5時から選ぶ） |
| P12 | データは端末の中だけ | localStorage に保存。書き出し・読み込み・全削除ができる |
| P13 | 見やすさと操作しやすさ | 文字12px以上、WCAG AAのコントラスト、タップ領域44px以上、動きを減らす設定への対応、色以外でも区別できる |
| P14 | フレンド機能は作らない | サーバーを持たないので作らない。人と比べる・さらす機能はなし |

## 5. やること／やらないこと

### やること（今回の範囲）

- はじめての設定（ようこそ → 体についての注意 → 週の目標ときっかけ → 最初の1分）
- 今日の画面（今週の進み具合、体の調子、今日のメニュー、休む、おかえり）
- 運動中の画面（人の動きのイラスト、合図、残り時間、音声、効果音、振動、中止）
- 完了画面（今日のぶん、できた・今週の進み・通算・きつさの確認・レベル変更の提案）
- 記録の画面（週ごとの記録、あと付けと削除、はじめと今の比較）
- 設定（目標、きっかけ、1日の区切り、音、文字の大きさ、テーマ、データの書き出し・読み込み・削除）
- ホーム画面に追加できるようにする（PWA）、オフラインでも開けるようにする
- GitHub Actions で GitHub Pages に自動で公開する

### やらないこと

- ログイン、サーバーへの保存、端末間の同期
- プッシュ通知（サーバーが必要なため）。きっかけは「◯◯の後に」という言葉で画面に出す
- フレンド、ランキング、シェア
- アクセス解析（データを外に出さないため）

## 6. データの扱い

- 保存先はブラウザの localStorage だけ。外部への送信はしない。
- **iPhone の Safari の注意**：Safari では、Safariを使った日で数えて7日間そのサイトを操作しないと、localStorage などのデータが消されることがある（WebKit のトラッキング防止）。ホーム画面に追加したウェブアプリは対象外。
  - → iPhone の Safari では「ホーム画面に追加」を案内する
  - → 記録の書き出し（バックアップ）を設定画面に置く
  - → 対応しているブラウザでは、データを消されにくくする仕組み（`navigator.storage.persist()`）を使う
- 保存データには版番号を持たせ、形式が壊れていても元のデータを別の場所に退避してから初期化する（黙って消さない）。

## 7. 公開の方法

- main ブランチに push すると、GitHub Actions がテストとビルドをして GitHub Pages に公開する。
- 公開URL：https://daisuke-awaji.github.io/kintore-habit/

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| iPhone の Safari で、しばらく開かないと記録が消える | ホーム画面への追加を案内する、書き出し、`persist()` |
| 音声ガイドが使えないブラウザがある | 日本語の音声がなければ話さず、画面の文字と効果音だけで進める |
| 画面を消さない機能（Wake Lock）が使えないブラウザがある | 使えなければ何もしない（画面に注意を出す） |
| 運動中にアプリを切り替える | 自動で一時停止する |
| 医療的な誤解 | 医療のアドバイスではないこと、痛みが出たら中止すること、持病がある人は医師に相談することを最初に出す |
| データの形式を将来変える | 版番号と移行の処理を用意する |

## 9. 完了の条件

- 公開URLで、はじめての設定から1分の運動・完了・記録までが最後までできる
- 再読み込みしても記録が残る
- ライト／ダーク、文字の大きさ「大」で表示が崩れない
- ドメインロジックのユニットテストが GitHub Actions で通る
