# 実装計画：1分筋トレ（kintore-habit）

計画書（`docs/PLAN.md`）の前提 P1〜P14 を、どう実装するかをまとめる。

## 1. 技術構成

| 用途 | 採用 | 理由 |
|---|---|---|
| ビルド | Vite | 静的ファイルとして出力でき、GitHub Pages にそのまま置ける |
| UI | React 18 + TypeScript | 画面の状態が多い（運動中・一時停止・中止など）ので、型と部品化で崩れにくくする |
| 保存データの検証 | Zod | localStorage の中身は壊れたり古い形式だったりするので、読み込み時に必ず検証する |
| テスト | Vitest | 日付・週・判定ロジックは間違えやすいので、ユニットテストで固める |
| 画面遷移 | 自前の小さなハッシュルーター（`#/log` など） | GitHub Pages は SPA の履歴APIと相性が悪いため。戻るボタンも効く |
| オフライン | 手書きの Service Worker | 依存を増やさない。ページは「ネット優先、だめならキャッシュ」、それ以外は「キャッシュを返しつつ裏で更新」 |

ライブラリは react / react-dom / zod の3つだけにする。

## 2. ディレクトリ構成

```
.github/workflows/deploy.yml   テスト → ビルド → Pages に公開
docs/                          計画書・実装計画・レビュー・モック
public/                        manifest.webmanifest, sw.js, アイコン
src/
  main.tsx, App.tsx            起動・画面の切り替え
  router.ts                    ハッシュルーター
  domain/                      画面に依存しないロジック（テスト対象）
    date.ts                    論理日付（1日の区切り）、週の計算、日本語の日付表示
    schema.ts                  保存データの型（Zod）と初期値
    storage.ts                 読み込み・保存・書き出し・読み込み直し・削除
    stats.ts                   今週の回数、達成した週、通算、おかえり判定、次の部位
    exercises.ts               種目とレベル、1分の流れ（タイムライン）、ポーズ
    menu.ts                    体の調子とおかえりから今日のメニューを決める
  state/AppData.tsx            データの Context と更新関数
  services/                    音声・効果音・振動・画面を消さない・端末判定
  components/                  人の動きのイラスト、週の表示、シート、アイコンなど
  screens/                     Onboarding / Home / Workout / Done / Log / Settings
  styles/                      色や余白のトークン、共通スタイル
```

## 3. データモデル（localStorage キー：`kintore-habit:v1`）

```ts
AppData {
  version: 1
  createdAt: string            // ISO
  onboarded: boolean
  startDate: string | null     // 'YYYY-MM-DD'（論理日付）
  settings: {
    weeklyGoal: 1 | 2 | 3 | 4  // 初期値 2
    dayBoundaryHour: 0..5      // 初期値 4
    anchor: string | null      // 「歯みがきの後」など
    voice, sound, vibration: boolean
    textSize: 'normal' | 'large'
    theme: 'system' | 'light' | 'dark'
  }
  sessions: Session[]
  restDays: string[]           // 回復日にした日
  weekGoals: Record<string, number>  // 週の開始日 → その週の目標（あとから目標を変えても過去の達成が消えないように）
  levels: { lower: 1..3, upper: 1..3, core: 1..3 }
  condition: { date: string, value: 'normal' | 'sore' | 'tired' | 'pain' } | null
  dismissed: string[]          // 一度閉じた案内
}

Session {
  id: string
  date: string                 // 論理日付
  at: string                   // 記録した時刻（ISO）
  kind: 'workout' | 'recovery' | 'other'
  area?: 'lower' | 'upper' | 'core' | 'recovery'
  exerciseId?: string
  level?: number
  durationSec: number
  completed: boolean           // 1分やりきったか（途中でやめても記録はする）
  feeling?: 'hard' | 'ok' | 'easy'
  backfilled?: boolean         // あと付け
  stoppedForPain?: boolean
}
```

- 読み込み時に Zod で検証する。失敗したら、元の文字列を `kintore-habit:corrupt:<時刻>` に退避してから初期データで始める。
- localStorage が使えない環境（一部のプライベートブラウズなど）では、メモリ上で動かし、画面に「この端末に保存できません」と出す。

## 4. ドメインロジックの仕様

### 4-1. 日付（`date.ts`）
- 論理日付 = 「現在時刻 − 区切りの時間」のローカル日付。区切りが4時なら、午前3:59は前日扱い。
- 週は月曜始まり。`weekStart(date)` は、その週の月曜日。
- 日付はすべて `'YYYY-MM-DD'` の文字列で扱い、計算するときはローカル時刻の正午に置いて誤差を避ける。

### 4-2. 集計（`stats.ts`）
- **回数は「やった日」の数**で数える（1日に何分やっても1回）。合計の分数は別に出す。
- 今週の回数 = 今週の中で、記録がある日の数。
- 達成した週 = 回数がその週の目標（`weekGoals` にあればそれ、なければ今の目標）以上の週の数。
- 通算 = 記録がある日の数。始めてからの日数 = 開始日から今日まで（開始日を1日目とする）。
- **おかえり判定**：過去に記録が1つ以上あり、今日の記録がなく、最後に記録か回復日を付けた日から3日以上あいている。
- **次の部位**：下半身 → 上半身 → 体幹 の順番。直前の筋トレの次の部位にする（回復のストレッチは順番に数えない）。

### 4-3. 今日のメニュー（`menu.ts`）

| 状態 | メニュー |
|---|---|
| ふつう | 次の部位を、今のレベルで |
| 筋肉痛 | 回復のストレッチ1分をすすめる（ほかの部位も選べる） |
| 疲れぎみ | 次の部位を、1段階軽く |
| 痛みがある | 痛む部位は休むよう案内し、回復のストレッチか休むをすすめる |
| おかえり | 次の部位を、1段階軽く |

### 4-4. 種目と1分の流れ（`exercises.ts`）

| 部位 | レベル1 | レベル2 | レベル3 |
|---|---|---|---|
| 下半身 | 椅子スクワット（3秒で座る・3秒で立つ ×10） | スクワット（2秒・2秒 ×15） | ゆっくりスクワット（4秒・2秒 ×10） |
| 上半身 | 壁に手をつく腕立て（2秒・2秒 ×15） | 膝つき腕立て（2秒・2秒 ×15） | 腕立て伏せ（3秒・2秒 ×12） |
| 体幹 | 膝つきプランク（15秒キープ×3、休けい10秒×2） | プランク（20秒キープ×2、休けい10秒×2） | 長めのプランク（25秒キープ×2、休けい10秒） |
| 回復 | 肩回し20秒 → 体の横を伸ばす20秒 → 太ももの裏を伸ばす20秒 | | |

- すべて跳ばない・道具なし（椅子と壁だけ）。
- どの種目も合計60秒。目標は時間だけ（回数は合図に合わせた目安として表示）。
- 1分の流れは「区間」の並び：`{ 合図: '下へ' | '上へ' | 'キープ' | '休けい' | ..., 秒数, 始まりのポーズ, 終わりのポーズ }`。

### 4-5. 人の動きのイラスト
- 横から見た棒人間を SVG で描く。関節（頭・首・肩・ひじ・手・腰・ひざ・足）の座標をポーズとして持ち、区間の進み具合に合わせて2つのポーズの間を補間する。
- 椅子や壁は小道具として描く。
- 「視差効果を減らす」設定の人には、なめらかな動きをやめ、合図が変わったときにポーズを切り替えるだけにする。

## 5. 画面の仕様

| 画面 | ハッシュ | 主な中身 |
|---|---|---|
| はじめに | `#/onboarding` | ようこそ → 体についての注意 → 週の目標ときっかけ → 最初の1分 |
| 今日 | `#/` | 日付ときっかけ、今週の進み（7日分の印と日付）、体の調子、今日のメニュー、休む、通算 |
| 運動 | `#/workout?area=&level=` | 開始前（見本・ポイント・注意）→ 3・2・1 → 運動中（合図・残り時間・イラスト）→ 一時停止／中止 |
| 完了 | `#/done?id=` | 今日のぶん、できた・今週の進み・通算・きつさ・レベル変更の提案・ホームへ／もう1分 |
| 記録 | `#/log` | 通算と達成した週、はじめと今の比較、週ごとの記録（日付をタップしてあと付け・削除） |
| 設定 | `#/settings` | 目標、きっかけ、1日の区切り、音声・効果音・振動、文字の大きさ、テーマ、データ、体についての注意 |

### 運動中の仕組み
- 時間は `performance.now()` で測り、一時停止中は進めない。
- アプリを切り替えたり画面を消したりしたら（`visibilitychange`）自動で一時停止する。
- 画面を消さない：`navigator.wakeLock` があれば使う。
- 音声：`speechSynthesis` で日本語の声があるときだけ話す（「はじめ」「半分」「あと10秒」「おわり」、キープや休けいの切り替え）。
- 効果音：Web Audio で、下へ／上へで高さの違う短い音。最後の3秒はカウントの音。
- 振動：`navigator.vibrate` があれば、区間の切り替えと終わりに。
- 中止：「痛い・やめる」で一時停止し、「楽な種目にする」「ここまでで終わる（記録する）」「記録せずに終わる」「つづける」を選べる。

## 6. 見た目とアクセシビリティ
- 色：白黒を基本に、できた印だけ緑。文字色は背景とのコントラスト比4.5以上、枠線や印は3以上。
- 文字：最小12px、本文16px。「大」にすると全体が約1.15倍。
- タップ領域：44px以上。
- 状態は色だけでなく、チェックの形や文字（「休」）でも表す。
- `prefers-reduced-motion` のときは繰り返しの動きを止める。
- 合図の変化は `aria-live` で読み上げソフトにも伝える（毎秒は伝えない）。

## 7. テスト
- Vitest で `src/domain` をテストする：論理日付の区切り、月曜始まりの週、月や年をまたぐ計算、今週の回数、達成した週（目標を変えた場合も）、おかえり判定、次の部位、体の調子ごとのメニュー、レベル変更、保存データの検証・退避・書き出しと読み込み、全種目が60秒になっていること。
- 画面は公開URLをブラウザで操作して確認する（はじめての設定から完了まで、再読み込み後も記録が残るか、ダーク、文字「大」）。

## 8. 公開（GitHub Actions）
- `main` への push で実行：`npm ci` → `npm test` → `npm run build` → `actions/upload-pages-artifact` → `actions/deploy-pages`。
- Vite の `base` は `/kintore-habit/`。
- Pages の公開方法は「GitHub Actions」に設定する。
